v3.0.0-beta2#

在 GitHub 查看此版本 。

Isaac Lab 3.0 Beta 2 以稳定和扩展 3.0 测试版功能为重点。在 v3.0.0-beta 基础上，新增并改进 Newton 支持（VBD、求解器耦合、Kamino、崎岖地形、传感器）、多后端物理、简化的训练和安装命令，以及不依赖 Kit 的工作流、可视化器、渲染、遥操作、学习模型导出、安装、CI 和文档。

此版本兼容最新发布的 Isaac Sim 6.0 。

警告

这是测试版本。 develop 分支仍在积极开发，在最终 3.0 发布前，可能继续出现不兼容变化、错误提示变化或性能调优。最新开发进展请查看 develop 分支。

主要亮点#

多后端稳定性改进#

首个 3.0 测试版引入的多后端架构，在 PhysX、Newton、OVPhysX、Isaac RTX、OVRTX 及无 Kit 执行路径上进一步完善。改进了后端选择、场景数据路由、克隆计划处理、传感器重置行为、运行时兼容性检查，以及请求不支持的物理、渲染器、可视化器组合时的错误报告。

Newton 物理与无 Kit 工作流#

扩展并稳定 Newton 和 OVPhysX 支持，以适应更大规模的无 Kit 训练及可视化工作流：

  • 在相关包中增加 Newton 射线投射器、坐标变换器、IMU/PVA、接触、关节力旋量、可变形物体及 VBD 耦合支持。

  • 为四足和双足机器人增加 Newton 崎岖地形运动预设，并为操作、导航及 Spot 环境补充 MJWarp 预设。

  • 补充 Newton 安装、支持功能、MJWarp、Kamino、VBD、求解器对比、Warp 环境迁移和 Newton 管理器抽象的文档。

  • 修复异构复制、克隆计划源解析、重置后的传感器旧数据、PhysX 仿真中的 Newton 可视化器更新，以及 Newton 相机/site 坐标系位姿。

  • 增加对 OvPhysX（无 Kit 版本的 PhysX）的初步实验性支持。

渲染、相机与 PPISP#

Isaac RTX、OVRTX 和 Newton Warp 的渲染功能均有广泛更新：

  • 新增 isaaclab_ppisp ，提供与渲染后端无关、符合物理规律的图像信号处理流水线，将 HDR 场景线性输出转换为 LDR 相机图像。

  • 配置 CameraCfg.isp_cfg 时，Isaac RTX、OVRTX 和 Newton Warp 渲染器支持 HDR 输出及内部 PPISP 处理。

  • 将平铺相机实现并入 Camera ，改善 Kit 和 Newton 可视化器中的平铺相机支持。

  • 修复 OVRTX 多 GPU 运行、克隆环境相机输出、临时文件处理、运行时缺失错误，以及可选 PPISP 安装的包解析。

  • 增加渲染正确性、图像对比、可视化器集成及性能测试。

可视化器与场景数据#

可视化器系统增强了与后端无关的场景数据支持：

  • 增加用于访问当前 InteractiveScene 的场景数据后端钩子。

  • 改进 PhysX、Newton 和 OVPhysX 场景数据提供器，让可视化器能一致地发现变换、接触及传感器。

  • 为 Kit 和 Newton 可视化器增加平铺相机视图。

  • 修复可视化器启动顺序、Kit 可视化器崩溃、PhysX 场景中的 Newton 可视化器更新，以及同时启用多个可视化器时的相机和视频录制行为。

遥操作、Mimic 与策略部署#

遥操作及模仿学习工作流已按 3.0 的组件更新：

  • 增加 Isaac Capture MCAP 录制/回放支持，以及用于 CI 回放的非交互式 teleop_replay_agent.py 。

  • 延迟导入可选的 isaacteleop ，使未安装 Isaac Capture 运行时也能解析任务配置。

  • 改进 CloudXR 默认值、XR 性能建议、原生键盘/游戏手柄/SpaceMouse 映射及 RMPFlow 遥操作行为。

  • Mimic 安装现在包含 isaaclab_teleop ，移除过时的 nvidia-srl-usd-to-urdf 依赖。

  • 增加 LEAPP 策略导出文档，修复 RSL-RL 循环策略导出、投影重力导出、检查点选择及策略部署指南。

安装、Docker 与 CI#

此版本简化配置，并对基础设施进行大量改进：

  • 新增根目录下实验性的 uv run train 和 uv run play 工作流，让全新仓库能够直接启动训练和回放，无需手动创建或激活环境。

  • 将安装额外依赖简化为 isaacsim 和 all ，替代旧的 tasks 、 rl 、 assets 等按子模块划分的额外依赖。

  • 将发布的 Isaac Sim Docker 镜像固定为 6.0.0，Python 仍固定为 3.12。

  • PyTorch 更新至 2.10.0 ：x86_64/Windows 使用 CUDA 12.8 wheel，aarch64 使用 CUDA 13.0 wheel。

  • 增加安装 CI、wheel 构建自动化、按包运行的测试器、Docker 数据卷及非 root 用户修复，以及已发布的镜像标签。

  • 改进 aarch64、DGX Spark、ARM Docker、Windows、uv 和 pip 安装文档。

  • 将第三方 GitHub Actions 固定到提交 SHA，改进 CI 清理、取消、分片、诊断及仅文档变更时的行为。

新增与扩展功能#

核心功能#

  • 增加 ProxyArray 及资产/传感器级属性缓存，加快重复数据访问。

  • 增加场景数据提供器 API 及后端中立的变换访问文档。

  • 增加模式配置文档及后端中立的可变形物体 API。

  • 增加 GPU 变换读取、资产写入性能优化及启动耗时分析工具。

物理与渲染后端#

  • 增加 OVPhysX 关节体、刚性物体集合、接触传感器、坐标系视图、场景数据后端及运行时安装诊断。

  • 增加 HDR 相机输出、PPISP 集成、可变形 API 迁移、射线投射器修复及多 GPU Fabric 坐标系视图支持。

  • 增加 Newton 可变形物体支持、刚体与可变形物体耦合、射线投射支持、求解器配置导出、接触访问器，并更新 Newton 包的固定版本。

学习与环境#

  • 增加统一的 train 和 play 命令行入口，通过 --rl_library 在 rsl_rl 、 rl_games 、 skrl 、 sb3 和 rlinf 之间分派。

  • 围绕共享分派辅助函数重构 scripts/reinforcement_learning/ 下各学习库的训练/回放脚本，减少重复的启动器及解析逻辑。

  • 为统一训练和回放脚本增加带类型的预设选择项，如 physics=physx 、 physics=newton_mjwarp 和 renderer=... 。例如： train --rl_library rl_games --task=Isaac-Cartpole-RGB-Camera-Direct-v0 physics=newton_mjwarp renderer=newton_renderer presets=rgb 。

  • 增加对不支持的后端、渲染器、可视化器组合的验证，错误提示更清楚。

主要亮点#

多后端物理架构#

Isaac Lab 3.0 引入 基于工厂的多后端架构 ，将仿真后端专用代码与核心 API 分离。资产及传感器类，如 Articulation 、 RigidObject 和 ContactSensor ，现在以抽象基类为基础，在专用扩展包中提供各后端实现：

  • isaaclab_physx ：完整 PhysX 后端（默认），包括可变形物体、表面夹爪、接触传感器、IMU 及坐标变换器。

现有的 isaaclab.assets 和 isaaclab.sensors 导入仍有效，工厂会在运行时自动分派到当前后端。

新的 isaaclab_newton 扩展支持 不依赖 Isaac Sim 运行环境，即无 Kit 模式。Newton 支持包括：

  • 关节体、刚性物体及刚性物体集合。

  • 接触传感器。

  • MuJoCo-Warp 求解器，具有可配置积分器（ implicitfast 、 euler ）及接触模型（ pyramidal 、 elliptic ）。

  • CUDA 图支持，用于高吞吐量仿真步进。

  • 20 多个环境的 Newton 兼容预设，涵盖运动、操作和经典控制。

四元数格式：WXYZ → XYZW#

Isaac Lab 中所有四元数现在采用 XYZW 顺序，与 Warp、PhysX 和 Newton 一致。写死的四元数值必须更新，提供的四元数查找工具可帮助定位和修复。

迁移指南#

施加外力和力矩：力旋量合成器#

关节体、刚体和刚性物体集合的 set_external_force_and_torque() 已弃用，改为新的可组合力旋量系统。

相关 PR：isaac-sim/IsaacLab#3287

新功能： - 持续力旋量合成器 ：施加跨仿真步持续生效的力/力矩，直到显式修改 - 瞬时力旋量合成器 ：只施加一个仿真步，之后自动重置 - 可组合性 ：支持在同一刚体上叠加多个力和力矩 - 混合坐标系支持 ：可组合局部与全局坐标系中的力旋量

迁移指南：

旧 API（已弃用）：

# Old method - overwrites previous forces
asset.set_external_force_and_torque(
    forces=torch.ones(1, 1, 3),
    torques=torch.ones(1, 1, 3),
    body_ids=[0],
    env_ids=[0],
    is_global=False,
)

新 API：

# Set initial permanent forces (replaces previous)
asset.permanent_wrench_composer.set_forces_and_torques(
    forces=torch.ones(1, 1, 3),
    env_ids=[0],
    body_ids=[0],
)

# Compose additional forces on the same body
asset.permanent_wrench_composer.add_forces_and_torques(
    forces=torch.ones(1, 1, 3),
    env_ids=[0],
    body_ids=[0],
    is_global=True,  # Mix local and global frames
)

# Add torques independently
asset.permanent_wrench_composer.add_forces_and_torques(
    torques=torch.ones(1, 1, 3),
    env_ids=[0],
    body_ids=[0],
)

# Apply forces and torques together with custom application points
asset.permanent_wrench_composer.add_forces_and_torques(
    forces=torch.ones(1, 1, 3),
    torques=torch.ones(1, 1, 3),
    positions=torch.ones(1, 1, 3),
    env_ids=[0],
    body_ids=[0],
)

瞬时力旋量（新增）：

# Apply forces for a single simulation step only
asset.instantaneous_wrench_composer.add_forces_and_torques(
    forces=torch.ones(1, 1, 3),
    env_ids=[0],
    body_ids=[0],
)

# Multiple instantaneous wrenches compose automatically
asset.instantaneous_wrench_composer.add_forces_and_torques(
    forces=torch.ones(1, 2, 3),  # Add more forces
    env_ids=[0],
    body_ids=[0, 1],
)
# These are automatically reset after write_data_to_sim()

主要差异：

  • set_forces_and_torques() 替换现有力旋量。

  • add_forces_and_torques() 与现有力旋量合成。

  • 持续与瞬时力旋量自动合成。

  • 瞬时力旋量在每个仿真步后自动清除。

应用场景： - 无人机 ：将推力与气动阻力、风扰动合成 - 船舶 ：施加浮力及波浪引起的运动

v2.3.0#

变更内容#

Isaac Lab 2.3.0 基于 Isaac Sim 5.1，改进灵巧操作、遥操作和学习工作流。新增具备高级训练功能的灵巧环境，为更多机器人及设备扩展表面夹爪和遥操作支持，并将 SkillGen 集成到 Mimic 模仿学习流水线，通过 cuRobo 实现 GPU 加速运动规划和基于技能的数据生成。

此版本的主要亮点包括：

  • 灵巧强化学习（DexSuite） ：新增两个采用 Kuka 机械臂与 Allegro 手的灵巧操作环境，支持自动域随机化（ADR）及种群训练（PBT）。

  • 表面夹爪更新 ：扩展表面夹爪以支持基于管理器的工作流，新增 SurfaceGripperAction 和 SurfaceGripperActionCfg ，以及展示表面夹爪和 RMPFlow 遥操作的多个环境。新增机器人及变体，包括配备 Robotiq 夹爪或吸盘的 Franka、UR10，以及 Galbot 和 Agibot。

  • Mimic - SkillGen ：Mimic 模仿学习流水线新增 SkillGen 支持，集成 cuRobo，将 GPU 运动规划与按技能分段的数据生成结合。cuRobo 采用专有许可条款，使用前请仔细阅读 cuRobo 许可证 。

  • Mimic - 移动操作 ：新增 G1 人形机器人环境，结合基于 RL 的移动与基于 IK 的操作。集成完整机器人导航系统，通过随机化桌面抓取/放置位置、目的地及地面障碍物扩充示范。将任务分为抓取、导航、放置阶段后，可从纯操作示范生成大规模移动操作数据集。

  • 遥操作 ：上半身逆向运动学控制器新增零空间姿态任务，在将冗余自由度约束到偏好的直立姿态时，允许人形任务中的腰部运动。同时新增 Vive 和 Manus 手套支持，提供更多遥操作设备选择。

移除 SimulationCfg 的 disable_contact_processing 标志#

我们从 isaaclab.sim.SimulationCfg 移除 disable_contact_processing ，避免用户需要处理这些仿真器细节。默认始终为 True；创建接触传感器后，会在内部将其设为 False。

此前， disable_contact_processing 的行为容易引起困惑。顾名思义，它控制底层 PhysX 物理引擎的接触报告。禁用该标志（注意这里的双重否定）意味着 PhysX 从求解器收集接触信息，并允许向用户报告；启用则不执行此操作，避免相关开销。

许多示例，如运动环境，将此标志设为 True，即 不应 报告接触。但 GPU 仿真绕过该标志，只有 CPU 仿真受影响，因此此前未发现问题。在 CPU 上运行相同示例时，就会出现不同的行为。

仍自行设置该标志的用户，应收到弃用警告，说明标志已移除并改用新的默认行为。

恢复旧渲染设置以改善画质#

Isaac Lab 2.0.0 采用了新的渲染设置，以提高平铺渲染的性能，但画质有所下降。这一变化尤其影响场景中的穹顶光照，而许多示例默认使用这类光照。

多位用户反馈，新设置在一些无需牺牲画质的场景（例如录制仿真视频）中也降低了渲染质量。因此，我们已恢复原先的默认渲染设置，使画质达到用户预期。

对于愿意降低画质以换取速度的用户，我们后续会提供相应指南。

迁移指南#

重命名 Isaac Sim 扩展#

之前，Isaac Sim 扩展遵循 omni.isaac.* 的约定，例如 omni.isaac.core 。在 Isaac Sim 4.5 中，Isaac Sim 扩展已被重命名为使用前缀 isaacsim ，替代 omni.isaac 。此外，许多扩展已被重命名并拆分成多个扩展，以便为更具模块化的框架做准备，用户可以通过使用应用模板进行定制。

Isaac Lab 中常用的以下 Isaac Sim 扩展已重命名：

  • omni.isaac.cloner --> isaacsim.core.cloner

  • omni.isaac.core.prims --> isaacsim.core.prims

  • omni.isaac.core.simulation_context --> isaacsim.core.api.simulation_context

  • omni.isaac.core.utils --> isaacsim.core.utils

  • omni.isaac.core.world --> isaacsim.core.api.world

  • omni.isaac.kit.SimulationApp --> isaacsim.SimulationApp

  • omni.isaac.ui --> isaacsim.gui.components

重命名 URDF 和 MJCF 导入器#

从 Isaac Sim 4.5 开始，URDF 和 MJCF 导入器已被重命名，以便与 Isaac Sim 中的其他扩展保持一致。导入器作为开源项目可以在 isaac-sim GitHub 上找到。

由于扩展名更改，Python 模块名称也已更改:

  • URDF 导入器: isaacsim.asset.importer.urdf （之前是 omni.importer.urdf ）

  • MJCF 导入器: isaacsim.asset.importer.mjcf （之前是:omni.importer.mjcf ）

从 Isaac Sim UI 中，URDF 和 MJCF 导入器现在可以通过文件 > 导入菜单直接访问，当在文件浏览器中选择相应的 .urdf 或 .xml 文件时。

URDF 导入器的变化#

Isaac Sim 4.5 更新了 URDF 导入器，新的界面便于配置机器人的 URDF 导入选项。Isaac Lab 的 URDF 转换器也作了相应更新。 isaaclab.sim.converters.UrdfConverterCfg 新增了一些设置，例如可通过 PDGainsCfg 和 NaturalFrequencyGainsCfg 配置关节驱动器的增益。

需要注意一项破坏性变更： gains 必须是 PDGainsCfg 或 NaturalFrequencyGainsCfg 类型。

必须为 PDGainsCfg 指定刚度，例如：

joint_drive=sim_utils.UrdfConverterCfg.JointDriveCfg(
    gains=sim_utils.UrdfConverterCfg.JointDriveCfg.PDGainsCfg(stiffness=None, damping=None)
)

必须为 NaturalFrequencyGainsCfg 指定 natural_frequency 。

重命名 Isaac Lab 扩展和文件夹#

对应于 Isaac Sim 4.5 的更改，我们也对 Isaac Lab 目录和扩展做了一些更新。所有之前位于 source/extensions 下的扩展现在直接位于 source/ 目录下。 source/apps 和 source/standalone 文件夹已被移动到根目录，并且现在分别称为 apps/ 和 scripts/ 。

Isaac Lab 扩展已重命名为:

  • omni.isaac.lab --> isaaclab

  • omni.isaac.lab_assets --> isaaclab_assets

  • omni.isaac.lab_tasks --> isaaclab_tasks

此外，我们已将之前的 source/standalone/workflows 目录拆分为 scripts/imitation_learning 和 scripts/reinforcement_learning 目录。RSL RL、Stable-Baselines、RL_Games、SKRL 和 Ray 目录位于 scripts/reinforcement_learning 下，而 Robomimic 和新的 Isaac Lab Mimic 目录则位于 scripts/imitation_learning 下。

为便于在项目中重命名 Isaac Lab 扩展，我们提供了一个 简单脚本 。它会遍历本地 Isaac Lab 项目的 source 和 docs 目录，替换旧目录名和导入路径。 该脚本会直接覆盖源文件，请自行评估风险后使用。

Isaac Lab 扩展的重构#

随着用于模仿学习数据生成的 isaaclab_mimic 加入，我们将原先 isaaclab_tasks 下的 wrappers 目录拆分为独立模块 isaaclab_rl 。这个新扩展包含 Isaac Lab 所支持各类强化学习库的专用封装。

新的 isaaclab_mimic 扩展也取代了 robomimic 目录下原有的模仿学习脚本。旧的数据采集和数据集准备脚本已移除，改用新的 Mimic 工作流。需要继续使用旧脚本的用户，可从此前的发布分支获取。

此外， isaaclab_assets 扩展也拆分为 robots 和 sensors 子目录，使各类预定义配置的组织更清晰。

例如，下列导入语句：

from omni.isaac.lab_assets.anymal import ANYMAL_C_CFG

应替换为：

from isaaclab_assets.robots.anymal import ANYMAL_C_CFG

迁移指南#

在仿真上下文中设置仿真设备#

此前，将仿真设备改为 CPU 时，还需设置其他仿真参数，例如禁用 GPU 物理仿真和 GPU 流水线，配置过程较为繁琐。现在，设备检查直接在仿真上下文中完成，用户只需通过配置对象指定设备。

此前：

sim_utils.SimulationCfg(device="cpu", use_gpu_pipeline=False, dt=0.01, physx=sim_utils.PhysxCfg(use_gpu=False))

现在：

sim_utils.SimulationCfg(device="cpu", dt=0.01, physx=sim_utils.PhysxCfg())

通过命令行设置仿真设备#

此前，用户通过命令行参数 --device_id 指定设备，但这种方式无法明确表达使用 CPU 的意图。因此，现在需要通过 --device 明确指定设备，而非仅提供设备 ID。有效的设备名称如下：

  • "cpu"：在 CPU 上运行仿真

  • "cuda"：在默认索引对应的 GPU 上运行仿真

  • "cuda:N"：在设备 ID 为 N 的 GPU 上运行仿真。例如，"cuda:0" 使用索引为 "0" 的设备。

上述改动也改变了部分脚本的命令行用法。

此前：

uv run python source/standalone/workflows/sb3/train.py --task Isaac-Cartpole --cpu

./isaaclab.sh -p source/standalone/workflows/sb3/train.py --task Isaac-Cartpole --cpu

现在：

uv run python source/standalone/workflows/sb3/train.py --task Isaac-Cartpole --device cpu

./isaaclab.sh -p source/standalone/workflows/sb3/train.py --task Isaac-Cartpole --device cpu

重命名独立脚本的遥操作设备命令行参数#

由于 AppLauncher 现在提供 --device 参数，它与部分独立脚本中指定遥操作设备的同名参数发生冲突。为解决这一问题，遥操作设备改由 --teleop_device 参数指定。

此前：

uv run python source/standalone/environments/teleoperation/teleop_se3_agent.py --task IsaacContrib-Lift-Cube-Franka-IK-Rel --num_envs 1 --device keyboard

./isaaclab.sh -p source/standalone/environments/teleoperation/teleop_se3_agent.py --task IsaacContrib-Lift-Cube-Franka-IK-Rel --num_envs 1 --device keyboard

现在：

uv run python source/standalone/environments/teleoperation/teleop_se3_agent.py --task IsaacContrib-Lift-Cube-Franka-IK-Rel --num_envs 1 --teleop_device keyboard

./isaaclab.sh -p source/standalone/environments/teleoperation/teleop_se3_agent.py --task IsaacContrib-Lift-Cube-Franka-IK-Rel --num_envs 1 --teleop_device keyboard

使用 Python 版本的容器工具脚本#

原先的 container.sh 在一个脚本中处理多种用途，例如构建 "base" 或 "ros2" Docker 镜像，以及集群部署，逐渐变得复杂。越来越多用户希望叠加自己的 Docker 配置，这也使 Bash 脚本难以维护。因此，本版本将其功能迁移到 Python 脚本，并将集群相关工具拆分到 docker/cluster 目录下的独立脚本中。

container.sh 仍保留向后兼容性，但内部会调用 Python 脚本 container.py 。建议直接使用 Python 脚本。

此前：

./docker/container.sh start

现在：

./docker/container.py start

强化学习工作流的视频分目录存储#

此前，用户可向 train.py 传入 --video 标志，在强化学习训练期间录制视频。视频保存在本次运行日志目录下的 videos 目录中。

应用户要求， play.py 也新增了策略推理时的视频录制功能。由于无法更改视频文件名的前缀，train 和 play 脚本录制的视频分别保存到 videos/train 和 videos/play 目录中。

不再支持在 Isaac Sim 4.1 中使用平铺相机#

Isaac Sim 4.2 修复了平铺相机渲染流水线中的多项问题，使继续支持 Isaac Sim 4.1 的平铺相机变得困难。因此，建议本版本 Isaac Lab 配合 Isaac Sim 4.2 使用，以获得最佳体验。

迁移指南#

重命名 SimulationCfg.substeps#

此前，用户设置的 omni.isaac.lab.sim.SimulationCfg.dt 和 omni.isaac.lab.sim.SimulationCfg.substeps 分别表示物理仿真时间步长和子步数。但“子步”含义不够明确：它可能指一个物理时间步 dt 内的积分步数，也可能指一个渲染步内的物理仿真步数。

由于代码中该属性表示后者，因此将其重命名为 render_interval ，以明确其含义。

移除已弃用的属性#

按照此前版本的弃用通知，我们移除了下列类和属性：

  • 事件中的 mdp.add_body_mass 方法，请改用 mdp.randomize_rigid_body_mass 。

  • managers.RandomizationManager 和 managers.RandomizationTermCfg 类，请改用 managers.EventManager 和 managers.EventTermCfg 。

  • omni.isaac.lab.sensors.FrameTransformerData 中的以下属性： target_rot_source → target_quat_w ； target_rot_w → target_quat_source ； source_rot_w → source_quat_w 。

  • omni.isaac.lab.assets.Articulation 和 omni.isaac.lab.assets.RigidObject 类中的 body_physx_view 属性。该视图的刚体名称顺序与关节体视图不同，容易造成混淆。
