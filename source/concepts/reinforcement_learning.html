强化学习#

Isaac Lab 为多个强化学习（RL）库提供统一的策略训练和评估流程。本页帮助你选择库、运行首个实验，并了解最常用的选项。

如果正在开始一个新的机器人项目，且不需要其他库的独有功能，建议从 RSL-RL 开始。

快速入门#

在 Isaac Lab 仓库中，使用 RSL-RL 训练 Cartpole 策略：

uv run isaaclab train --rl_library rsl_rl --task Isaac-Cartpole

训练默认以无界面模式运行，并将检查点和 TensorBoard 日志写入 logs/rsl_rl/ 。

在交互式可视化器中评估最新的兼容检查点：

uv run isaaclab play --rl_library rsl_rl --task Isaac-Cartpole \
    --checkpoint latest --num_envs 32 --viz newton

train 和 play 命令适用于所有受支持的强化学习库。

选择强化学习库#

所有受支持的库使用相同的 Isaac Lab 环境，但算法、配置方式和预期工作流程不同。应根据实验需要的功能选择，而不是仅凭一次吞吐量测试结果。

库

适用场景

运行命令时，选择对应的 uv extra 来安装可选依赖：

uv run --extra skrl isaaclab train --rl_library skrl --task Isaac-Cartpole
uv run --extra rl-games isaaclab train --rl_library rl_games --task Isaac-Cartpole
uv run --extra sb3 isaaclab train --rl_library sb3 --task Isaac-Cartpole
uv run --extra torchrl isaaclab train --rl_library torchrl --task Isaac-Cartpole
uv run --extra torchrl isaaclab play --rl_library torchrl --task Isaac-Cartpole --checkpoint latest

典型训练流程#

开始长时间训练前，先用小规模冒烟测试验证环境和完整训练路径。

首先，不使用强化学习库，检查任务能否正常重置和步进：

uv run isaaclab random_agent --task Isaac-Cartpole --num_envs 16

然后，在少量环境上运行几次训练迭代：

uv run isaaclab train --rl_library rsl_rl --task Isaac-Cartpole \
    --num_envs 64 --max_iterations 10

两个命令都成功后，移除冒烟测试的覆盖参数，使用任务调好的默认值。

观察训练#

在另一个终端启动 TensorBoard：

uv run python -m tensorboard.main --logdir logs

关注多次迭代中的趋势：

  • 平均奖励 通常应逐步提高，但其绝对值取决于任务。

  • 平均回合长度 取决于任务。平衡任务中较长回合通常有益，但目标完成任务未必如此。

  • 吞吐量 有助于在调整环境数量、传感器或渲染后识别系统瓶颈。

  • 损失、熵、KL 散度和动作标准差 有助于发现更新不稳定或探索停滞。具体指标名称因库而异。

评估策略#

使用 play ，并选择下列检查点选择器之一：

选择器

行为

latest

从最新的兼容本地运行中，加载步数最高的检查点。

best

如果库记录了最佳或最终检查点，则加载它；否则回退到 latest 。

pretrained

为受支持的任务和后端下载已发布检查点。

/path/to/checkpoint

加载指定检查点。

例如，运行最佳本地检查点并录制短视频：

uv run --extra video isaaclab play --rl_library rsl_rl \
    --task Isaac-Cartpole --checkpoint best --video --video_length 200

提示

play 会调用环境配置的 play_mode() 方法，将场景限制为最多 50 个环境，并根据工作流程禁用观测噪声或扰动。可在任务配置中覆盖该方法，自定义回放行为。

预训练检查点#

已发布的预训练检查点仅覆盖受支持的核心任务，可用性还可能因强化学习库和后端组合而异。其他已注册任务（包括贡献任务）不在发布的检查点集合中。

传入 --checkpoint pretrained ，加载与解析后任务配置匹配的已发布策略。该选择器不保证每个已注册任务都有对应文件；如果匹配文件尚未发布，命令会报告不可用并退出。此时请在本地训练任务，再使用 latest 或明确的检查点路径。

维护者可以使用 scripts/tools/train_and_publish_checkpoints.py 生成推荐的核心任务检查点矩阵。通过 --list --all --core ，可列出当前源代码计划发布的任务和后端组合。该矩阵不会实时检查远程资产存储；只有检查点上传后，列出的组合才能通过 --checkpoint pretrained 使用。

uv run python scripts/tools/train_and_publish_checkpoints.py \
    --list --all --core

恢复训练#

从最新兼容检查点恢复：

uv run isaaclab train --rl_library rsl_rl --task Isaac-Cartpole \
    --checkpoint latest

加载明确指定的检查点时，应使用训练时相同的任务、智能体、机器学习框架和观测/动作预设。检查点保存策略状态，无法让不兼容的观测或动作变得兼容。

配置实验#

每个任务为其支持的库注册一个或多个智能体配置。建议从 source/isaaclab_tasks/isaaclab_tasks/<task-family>/.../agents/ 下最接近、持续维护的配置开始，而不是从零编写。

查找任务和智能体#

列出已注册任务，然后查看任务专属帮助：

uv run python scripts/environments/list_envs.py
uv run isaaclab train --rl_library rsl_rl --task Isaac-Cartpole --help

通过 --agent 选择其他已注册配置。例如：

uv run isaaclab train --rl_library rsl_rl --task Isaac-Cartpole \
    --agent rsl_rl_with_symmetry_cfg_entry_point \
    --run_name ppo_with_symmetry

智能体配置格式因库而异：

  • RSL-RL 使用继承 RslRlBaseRunnerCfg 的 Python 配置类。

  • RL-Games、skrl 和 Stable-Baselines3 使用各库特有的字典或 YAML 文件。

  • RLinf 使用专门的 VLA 后训练配置。

任务提供多种观测或动作预设时，应选择网络与所选预设匹配的智能体。

提示

省略 --rl_library 时， train 和 play 加载任务注册的 default_agent 。大多数核心任务默认使用 RSL-RL；多智能体 Pendulum 任务默认使用 skrl。

通过 Hydra 覆盖配置#

Hydra 允许在常规命令行选项后覆盖环境和智能体配置：

uv run isaaclab train --rl_library rsl_rl --task Isaac-Cartpole \
    --seed 2024 --run_name cartpole_seed_2024 \
    env.actions.joint_effort.scale=10.0 \
    agent.algorithm.learning_rate=0.0005

引号规则、列表值和多次运行的参数扫描，见 Hydra 配置系统 。

选择后端和预设#

任务可为物理、渲染、观测、动作及其他领域提供命名选择器。将不带前导短横线的选择器附加到命令后：

uv run isaaclab train --rl_library rsl_rl --task Isaac-Cartpole \
    physics=newton_mjwarp

uv run isaaclab train --rl_library rsl_rl \
    --task Isaac-Cartpole-Camera-Direct \
    physics=newton_mjwarp renderer=newton_renderer presets=rgb

并非每个任务都支持所有后端。任务声明的预设见 后端与预设 。

重要

训练和回放应使用相同的物理、渲染器、领域及观测/动作预设。改变观测或动作预设可能改变策略架构，导致检查点形状错误。这是预期行为，反映了所选配置对策略接口的约定。

扩大训练规模#

Isaac Lab 从多个并行环境收集经验。 --num_envs 控制仿真实例数量。增大该值可提高采样速度，直到仿真开销、优化器结构或显存成为瓶颈。可按需通过 --num_envs 扩大或缩小规模，但更多环境不一定使训练更快。

Isaac Lab 还支持 RSL-RL、RL-Games 和 skrl 的分布式训练。跨多 GPU 扩展训练的详情见 多 GPU 和多节点训练 。

专用工作流程#

标准训练流程足以满足大多数任务。以下流程适用于迁移已有策略、训练多个智能体、使用 JAX 或对视觉-语言-动作模型进行后训练。

RSL-RL 蒸馏#

蒸馏将行为从训练好的 教师 策略传递到 学生 策略。学生学习复现教师的动作，通常使用不同的观测集合或更小的网络。当教师使用的信息在部署时无法获得，这种方法很有用。例如，可以先训练基于状态的策略，再将其蒸馏为基于视觉的策略。

首先训练教师：

uv run isaaclab train --rl_library rsl_rl \
    --task Isaac-Velocity-Flat-AnymalD

然后选择已注册的蒸馏智能体，并加载教师检查点：

uv run isaaclab train --rl_library rsl_rl \
    --task Isaac-Velocity-Flat-AnymalD \
    --agent rsl_rl_distillation_cfg_entry_point \
    --checkpoint /path/to/teacher.pt

任务和蒸馏配置决定教师与学生可获得的观测。请确保检查点由兼容的教师配置生成。

skrl 多智能体训练#

多智能体强化学习训练多个在同一环境中行动的智能体。skrl 支持两种常用方法：

  • MAPPO 在训练价值函数时使用所有智能体的信息，但运行时各智能体仅根据自身观测行动。这种集中训练、分散执行的方法有助于学习协调行为。

  • IPPO 独立训练各智能体。它更简单，是实用的基线，但优化时不会显式使用其他智能体的信息。

例如，使用 MAPPO 训练 Shadow Hand 物体交接任务：

uv run --extra skrl isaaclab train --rl_library skrl \
    --task Isaac-Shadow-Handover-Direct \
    --algorithm MAPPO

通过 --algorithm IPPO 运行对应的独立策略流程。所选任务必须提供算法支持的多智能体接口。

使用 JAX 进行 skrl 训练#

skrl 也可以使用 JAX 代替 PyTorch 训练策略，适合接入基于 JAX 的学习系统，或试验 JAX 编译与执行：

uv run --extra skrl isaaclab train --rl_library skrl \
    --task Isaac-Reach-Franka \
    --ml_framework jax

使用此流程前，请安装与平台匹配、支持 CUDA 的 JAX 版本。JAX 默认预分配显存，因此要确保仿真和学习器能够共享可用显存。参见 skrl 安装指南 和 JAX 安装指南 。

RLinf VLA 后训练#

视觉-语言-动作（VLA）模型将视觉观测和语言指令映射为机器人动作。RLinf 使用强化学习，将预训练 VLA 模型适配到具体任务，通过任务奖励而不只是示范数据改善其行为。

提供 RLinf 实验配置和待后训练的基础模型：

uv run --extra rlinf isaaclab train --rl_library rlinf \
    --config_name isaaclab_ppo_gr00t_assemble_trocar \
    --model_path /path/to/base_model

相比从零训练小型策略，VLA 后训练通常需要更多显存。安装、分布式执行、配置和评估见 VLA 模型的强化学习后训练 。

通过 Python 调用#

下游应用和自动化脚本可以调用与命令行相同的训练分发器。直接构造请求无需创建 argparse.Namespace ，并为从 Python 启动训练提供稳定接口：

from isaaclab_rl import TrainingRequest, train

train(
    TrainingRequest(
        backend="rsl_rl",
        task="Isaac-Cartpole",
        max_iterations=100,
    )
)

回放时，将 PlaybackRequest 与 play() 配合使用。所选强化学习库理解的选项放入 backend_args ；Hydra 覆盖参数和预设选择器放入 hydra_args 。

故障排除#

内存不足#

首先减小 --num_envs 。这通常能在不改变任务本身的情况下最大程度降低内存用量。对于基于相机的任务，还可考虑减小图像分辨率、采集视图数量、轨迹采样长度或策略规模。

性能测试时禁用交互式可视化器。碰撞几何、接触和可变形物体占用的仿真内存，与策略及轨迹采样缓冲区相互独立。

使用 JAX 时，除仿真内存外，还需考虑其默认显存预分配。

观测或策略中出现 NaN#

NaN 通常源于不稳定的仿真或无效重置状态，随后传播到观测、奖励和学习器中。尽可能在不训练的情况下复现故障，并定位第一个变为非有限值的量。

请检查：

  • 重置时的关节位置、速度和物体位姿；

  • 执行器增益、限制和动作缩放；

  • 接触几何、质量、惯量及异常大的冲量；

  • 物理时间步长、子步数和求解器迭代次数；以及

  • 包含不安全除法、归一化或平方根运算的奖励和观测项。

修复无效状态或计算，而不是通过截断全部策略输入来掩盖问题。然后重新执行训练冒烟测试。

训练稳定，但没有学会任务#

调整超参数前，先验证环境接口约定：

  • 动作控制了预期关节；

  • 观测随环境变化而变化；

  • 智能体取得进展时，奖励增加；以及

  • 终止和重置在预期条件下发生。

与最接近、持续维护的任务配置对照，然后每次只改变一个因素。各实验都应记录任务、强化学习库、物理后端、领域预设、种子、环境数量、智能体配置和 Hydra 覆盖参数。缺少这些信息时，看似细微的配置差异可能被误判为算法性能退化。

检查点无法加载#

确认回放或恢复训练命令使用与原始运行相同的强化学习库、任务、智能体配置、机器学习框架和观测/动作预设。张量形状错误通常意味着其中一项发生了变化。

可用时优先使用 latest 或 best 检查点选择器。清单发现机制会在尝试加载检查点前过滤不兼容的运行。
